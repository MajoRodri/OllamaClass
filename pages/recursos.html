// Criterio ético

Ficha de Criterio Ético - IA Local

Riesgos, limitaciones y responsabilidades del uso de modelos de lenguaje en entornos locales.

Ejecutar un LLM de forma local elimina la dependencia de servicios externos y protege la privacidad de los datos, pero no exime al usuario de responsabilidad ética. El modelo no razona ni comprende: predice texto estadísticamente probable. Su uso conlleva riesgos de sesgo, desinformación y exclusión tecnológica que deben conocerse antes de aplicarlo en contextos reales.
Sesgos heredados

Los modelos fueron entrenados sobre corpus masivos de internet que contienen sesgos culturales, de género e ideológicos. El modelo puede reproducirlos o amplificarlos sin que el usuario lo note.

Alucinación

El modelo genera texto con alta confianza aunque sea incorrecto: fechas, cifras, referencias y código pueden ser plausibles pero falsos. Todo resultado crítico debe ser verificado por el usuario.

Privacidad relativa

La ejecución local protege los datos de terceros externos, pero no garantiza privacidad absoluta. Los logs, el historial y los archivos de caché locales pueden exponer información sensible si el equipo no está securizado.

Brecha de acceso

Correr modelos de calidad requiere al menos 8–16 GB de RAM/VRAM. Esto crea una barrera de acceso que excluye a usuarios con hardware de gama baja, generando una desigualdad en quién puede beneficiarse de la herramienta.

Uso sin filtros externos

A diferencia de servicios cloud, los modelos locales no tienen moderación de contenido centralizada. El usuario asume plena responsabilidad sobre su uso: puede generar desinformación o contenido dañino si no se aplica criterio ético.

Conocimiento desactualizado

El modelo tiene una fecha de corte de entrenamiento y no accede a internet. No conoce eventos recientes. Usarlo como fuente de información actual sin advertencia puede inducir a errores en quien lo consulte.

// Primeros auxilios

Errores comunes - Troubleshooting

Si algo falla durante la instalación o la demo, revisa aquí antes de entrar en pánico.

ollama: command not found
Ollama no está instalado o no se añadió al PATH correctamente. Solución: descarga el instalador desde ollama.com, instala y reinicia la terminal (o el equipo) antes de volver a intentarlo.
La descarga del modelo se corta o tarda demasiado
Los modelos pesan entre 2 y 8 GB. Solución: asegúrate de tener conexión estable. Si se corta, vuelve a ejecutar ollama pull nombre-modelo - retoma desde donde quedó. Evita usar WiFi público.
El modelo no carga o el sistema se congela
Memoria insuficiente. Solución: cierra todas las aplicaciones abiertas y elige un modelo más ligero. Para 8 GB de RAM, usa modelos de 3B o 7B con cuantización Q4. Comprueba la RAM disponible antes con el gestor de tareas.
Respuestas muy lentas (menos de 2–3 tokens/segundo)
El modelo está corriendo en CPU, no en GPU. Solución: verifica que los drivers de tu tarjeta gráfica estén actualizados. Ejecuta ollama run modelo y busca en los logs si aparece GPU layers: 0 - si es así, el offload no está activo. Prueba reinstalar Ollama.
Chatbox / Open WebUI no se conecta a Ollama
La interfaz no encuentra el servidor local. Solución: asegúrate de que Ollama esté corriendo (abre una terminal y ejecuta ollama serve). En la configuración de la interfaz, la URL del servidor debe ser http://localhost:11434.
Error al crear el Modelfile (ollama create falla)
Ruta o nombre de archivo incorrecto. Solución: el archivo debe llamarse exactamente Modelfile.txt y el comando debe ejecutarse desde la misma carpeta donde está guardado: ollama create mi-asistente -f ./Modelfile.txt
